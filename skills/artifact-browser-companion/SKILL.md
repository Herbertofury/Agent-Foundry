# Artifact Browser Companion



Build a companion app around the user's canonical research artifacts instead of creating a disconnected copy. Preserve source provenance, make refresh deterministic, and make live project browsing first-class.

## Zero-Loss composition

Treat this as a domain overlay on `zero-loss-chat-accelerator` and any still-applicable project/file-format skill. Preserve canonical source IDs/revisions, normalized-data hash, loaded schemas/evidence, last checkpoint/mutation/test, blocker, no-repeat history, and exact next action. Skill activation or a handoff to spreadsheet/DOCX/PDF tooling must not restart source enumeration or normalization.

Use single-flight reads, implementation crossing, retry-with-new-information, checkpoint-before-long-gate, and monotonic progress. After two unchanged waves, change strategy. Do not enumerate the whole Drive/Library/skill directory when exact source IDs or prior build metadata already resolve the source set.

## Core contract

Unless the user overrides it:

1. Keep canonical Sheet/Doc/PDF/source artifacts authoritative; never silently fork the dataset.
2. Produce a local-first catalog/explorer that works offline from a verified snapshot.
3. For desktop output, use real Chromium-backed browser tabs, not iframe-only embedding.
4. Expose obvious `Open in your browser` and `Copy URL` actions for the exact active/project URL.
5. Treat embeds/previews as optional enhancements, never a dependency.
6. Never expose Node.js/privileged app APIs to untrusted remote content.
7. Land named project/source links on the exact known page.
8. Use real source-grounded project/author/gallery assets; do not synthesize imagery unless the current message explicitly asks for image generation.
9. Make every visible control functional; no fake buttons/status.
10. Keep current artifact names clean; keep build/scour/history metadata inside the app.
11. Preserve superseded releases in `History` when the surrounding workflow expects lineage.
12. Build/verify a reproducible source package alongside the runnable app.

## Output lanes

Use the lane(s) that materially help the request:

- **Portable web snapshot:** self-contained HTML for quick/offline browsing, galleries, filters, notes/favorites where storage permits, and direct links.
- **Desktop browser companion:** Electron with `WebContentsView` or the current supported equivalent for real live browser tabs.

Do not build both merely as ceremony when the user only needs one. When both are useful, share one normalized dataset/build metadata pipeline so work is not duplicated.

## Workflow

### 1. Resolve canonical sources once

Identify the exact current structured/narrative/fixed sources, project URLs/media provenance, and any prior companion build/history.

Prefer stable provider IDs + source hashes/revisions over filenames. On continuation, compare revisions/hashes to the last build metadata and process only changed sources. For spreadsheet/DOCX/PDF extraction/editing, invoke the matching format skill as a bounded subroutine and return with source identity intact; do not duplicate its logic here.

Read `references/source-model.md` before defining/changing the normalized schema. Do not reread it on every refresh after the schema version is already known.

### 2. Normalize deterministically

Create one canonical app model with collision-proof stable IDs. At minimum preserve item identity/name/summary, categories/tags/platform/version data, authors, source URLs/verification, gallery provenance, and exact source locations.

Preserve source-specific status, notes, evidence, generation/scour metadata, caution flags, and provider homes when they improve browsing or update correctness.

### 3. Build the catalog experience

Read `references/ui-ux-standard.md` once for a new/materially changed UI. Apply the relevant quality floor:

- instant global search and structured query operators;
- faceted filters and sortable table/card/gallery views;
- saved views, favorites, notes, compare, recently viewed;
- provenance + last-sync/build status;
- exact project detail actions;
- keyboard/accessibility/reduced-motion support;
- CSV/JSON export of current filtered results;
- deep-linkable state when practical;
- no viewport culling that makes records unavailable to search/navigation.

For media-heavy catalogs, read `references/gallery-standard.md` only when the gallery contract is in scope.

### 4. Build the desktop browser workspace

Read `references/browser-shell.md` only for the desktop lane. Required browser UX includes real tabs, back/forward/reload/stop, address bar, tab lifecycle, persistent normal session/cookies, controlled pop-up/new-tab handling, downloads with visible state, find/zoom, history/session restore when practical, truthful errors, and exact external-browser/copy-URL actions.

Do not implement remote sites as an iframe collection and do not require them to permit embedding.

### 5. Secure remote content

Enforce `nodeIntegration: false`, `contextIsolation: true`, sandboxing, no broad privileged preload bridge, protocol validation, mediated permissions, local-UI/remote-content isolation, and a dedicated persistent browser session partition. Keep Electron/current Chromium dependencies current without crippling normal browsing.

### 6. Make updates cheap

Every build must record canonical source IDs/URLs, source revisions/hashes, normalized dataset hash, item/media counts, build timestamp/version, and generator/standard version.

Generate one update command/script. Hash/revision comparison must skip unchanged sources and unchanged media. When connected Drive/project tooling is used, update stable current artifact IDs in place and preserve superseded builds under History only when genuinely superseded.

Read `references/update-standard.md` only when implementing/changing synchronization. If recurring monitoring is requested, use a condition-watch that does nothing when hashes are unchanged.

### 7. Scaffold only when needed

For a new desktop companion:

```bash
python scripts/scaffold_companion.py --name "Project Companion" --output /path/to/project
```

Replace the starter catalog/UI; never ship it unchanged. Validate normalized data with:

```bash
python scripts/validate_catalog.py /path/to/catalog.json
```

Execute any added/modified scripts during the run.

### 8. Verify without retest ceremony

Read `references/qa-standard.md` before closeout. During iteration, test the changed path; run the complete applicable QA matrix once at convergence and rerun only after a mutation that can invalidate it.

Verify normalized count/unique IDs, exact direct links, source/hash metadata, real/deduplicated media, search/query/filter/sort/views/favorites/notes/compare/export/theme, exact project-to-live-tab navigation, browser controls, exact external-open URL, session persistence where testable, pop-up/download/error/permission behavior, restart state, console/page errors, responsive snapshot layout, and actual packaged-launch identity.

Do not call syntax/lint alone completion.

## Stall-safe external work

- Reuse source IDs, browser/session identities, hashes, and build metadata already known in the current capsule.
- Do not perform a full source re-enumeration after a file-format skill returns; consume its result.
- Do not redownload unchanged media or revalidate unchanged exact URLs without a freshness reason.
- Batch source reads/media checks where supported.
- If a connector/provider fails unchanged, try only a materially different supported route; do not loop listing/auth/search calls.
- Before long packaging/Electron/runtime gates, checkpoint the coherent source/build state; observe exact run/PID milestones rather than repeatedly rediscovering process state.

## Naming and persistence

Use clean current names such as `Project Name - Explorer.html`, `Project Name - Companion.exe`, and `Project Name - Companion Source.zip`; keep dates/counts/hashes/lineage inside metadata. Preserve the reusable output in the canonical repository and connected Drive according to the governing project workflow.

## Challenge pass

Before closeout, look once for one material improvement such as richer queries, source-health visibility, session recovery, smarter gallery dedupe, provider-aware actions, accessibility, or faster delta refresh. Implement it when evidence shows real value and it does not regress the core contract; do not turn the challenge pass into another research loop.
