## 1. Decision principle

Maximize risk-adjusted expected revenue per unit of elapsed time while favoring paths that ChatGPT can execute directly. The best idea is not the one with the largest theoretical market; it is the one with strong present demand, user fit, a short conversion path, and high execution coverage.

## 2. Opportunity lanes

### A. Existing-asset monetization

Look for code, plugins, utilities, templates, research, datasets, automation, documentation, or internal workflows that solve a recurring external problem.

Strong patterns:
- paid edition or commercial license for a useful existing tool
- paid setup, customization, migration, or support around an existing project
- packaged templates/checklists/automation bundles
- hosted or managed version of a proven local utility
- paid integration work for users already adopting the tool

Evidence to seek:
- existing users, stars, forks, downloads, questions, support requests, issue traffic, repeated pain points, comparable paid products

### B. High-value services

Prefer narrow outcome-based offers over generic "freelancing."

Examples:
- security hardening or audit for a defined system
- server maintenance or incident-prevention package
- browser extension or automation implementation
- migration/integration work
- performance/reliability repair
- code/repository rescue for a concrete failing workflow

Structure each offer as:
`Buyer + costly problem + concrete deliverable + turnaround + proof + fixed/anchored price + next step`

### C. Bounties and rewards

Use only programs with explicit authorization and published scope. Favor targets where the user's demonstrated technical strengths fit the bounty class and the reward is meaningful relative to investigation time.

Score down:
- vague scope
- historically low payout or high duplicate rate
- programs requiring large speculative effort before eligibility is clear

### D. Narrow digital products

Build around a verified pain point, not an abstract idea. Good products are small enough to ship rapidly and valuable enough to charge for immediately.

Examples:
- specialized developer/operations utility
- workflow automation pack
- diagnostic tool
- migration/conversion utility
- professional template bundle
- premium extension/plugin feature set

A product is not ready to monetize until there is a working deliverable, clear buyer, price, product page/listing copy, delivery path, and payment handoff.

### E. Retainers and recurring support

Convert one-off technical work into ongoing monitoring, updates, maintenance, support, or managed operations when the buyer has a persistent problem.

Prefer explicit service levels and bounded scope. Recurring revenue is valuable only if servicing cost remains controlled.

### F. Audience/content/affiliate

Use this lane only when the user already has distribution, search demand is unusually strong, or the content itself directly generates qualified leads for a higher-value offer. Treat building an audience from zero as a long-horizon strategy, not the default time-to-cash choice.

## 3. Scoring dimensions

Score each from 0 to 10:

- `revenue_potential`: realistic near-term monetary upside
- `time_to_cash`: 10 means very fast, 0 means very slow
- `demand_evidence`: strength and freshness of buyer-demand evidence
- `skill_fit`: match to demonstrated user capability/assets
- `autonomy`: fraction ChatGPT can execute with available tools
- `repeatability`: ability to repeat or scale after first conversion
- `capital_efficiency`: 10 means little/no upfront capital
- `competition_advantage`: defensibility or differentiation
- `confidence`: confidence in assumptions and source quality

Penalties from 0 to 10:

- `setup_burden`
- `platform_dependency`
- `identity_payment_blocker`
- `uncertainty`

The bundled scorer combines these into a 0-100 score. Use judgment to override only when strong evidence is not represented by the numeric fields, and explain the override.

## 4. Kill criteria

Drop or deprioritize an opportunity when any of these persist after a reasonable test:

- no concrete buyer can be identified
- current demand evidence is weak or stale
- the path to payment is unclear
- the required non-delegable setup dominates the workflow
- expected hourly value falls below another available lane
- repeated targeted outreach gets no qualified response
- product interest does not convert after pricing/value proposition tests
- a bounty/reward path is outside explicit authorized scope

Do not continue a weak idea merely because work has already been invested.

## 5. Conversion design

Every revenue path must answer:

1. Who pays?
2. What painful or valuable outcome are they buying?
3. What exactly is delivered?
4. Why should they trust this offer?
5. What does it cost?
6. What action starts the transaction?
7. How is delivery completed?
8. What evidence proves payment or commitment?

If any answer is missing, repair the conversion path before adding more features.

## 6. Outreach discipline

- Research the recipient before contact.
- Mention a specific observed need, project, problem, or opportunity.
- Lead with the outcome, not a biography.
- Include one credible proof point or sample when available.
- Make one clear low-friction call-to-action.
- Follow up based on evidence and reasonable cadence.
- Stop when the recipient declines or the opportunity is clearly cold.
- Never manufacture urgency, references, results, or social proof.
