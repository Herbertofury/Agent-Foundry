# Getting Started

## For chats
Select the relevant component from the [chat catalog](Skills-Catalog). The nine flagship workflows cover Governance, Zero-Loss, Project Brain, Minecraft development/repair, visual QA, artifact browsing, revenue and Skill creation. Use the narrowest workflow and preserve accepted state across selected overlays. Availability depends on the installed chat capabilities.

## For coding agents and repositories
Keep local setup, commands, architecture, restricted paths and acceptance criteria in project-owned AGENTS.md and scoped instructions. Review the existing 18 product invariants and relevant standards. Do not import the chat catalog or universal chat contract as automatic policy.

Use the [repository adoption plan](Repository-Governance-Sync) against an explicitly selected isolated project. Preserve customization and review integration before adoption. No rollout to other repositories is configured.

For substantial invention, use bounded challenger research. For stack decisions, consult current official support/compatibility sources and the promotion gate. For UI, establish a brief and inspect/exercise the real result. See [Stack and Design Quality](Stack-and-Design-Quality).
